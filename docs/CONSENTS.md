# Правовые документы и реестр согласий (152-ФЗ)

Админка → «Документы и согласия» (`/admin/legal`). Миграция `packages/database/migrations/013_legal_consents.sql`.

## Документы и версии
- Виды: политика обработки ПД, согласие на обработку ПД, оферта, согласие на рассылки.
- У каждого вида одна действующая версия. Новая версия добавляется кнопкой «Новая версия»: номер, дата вступления, ссылка на текст (страница сайта или PDF из медиатеки).
- Править документы может только администратор (область `legal`).
- `GET /api/legal` (apps/web, без входа) отдаёт действующие версии для экрана входа приложения.

## Реестр
- Запись появляется, когда:
  - клиент впервые входит в приложение по коду или регистрируется с согласием (apps/web, `source = app`);
  - на сайте отправлена форма с галочкой согласия (`/api/lead`, `source = site`);
  - партнёр подаёт анкету (`source = partner`), вместе с версией договора партнёра.
- Согласия, данные до появления реестра, перенесены с версией «до учёта версий».
- Хранится контакт, документ и версия, дата, источник, IP и браузер.
- Реестр видят администратор и клиентский сервис (область `consents`). Выгрузка в CSV пишется в журнал.

## Отзыв согласия
- Клиент из приложения: `DELETE /api/account/consents` (по токену). `GET /api/account/consents` отдаёт его согласия. Экрана в приложении пока нет, нужна сборка.
- По письму или звонку: кнопка «Отозвать» в реестре или в карточке клиента, с обязательным основанием.
- При отзыве ставится срок `stop_by` = дата отзыва + 30 дней (ст. 21 ч. 5). Отозванные со сроком видны на карточке «Отозваны, срок идёт». Обезличивание аккаунта делается отдельно (удаление аккаунта).
