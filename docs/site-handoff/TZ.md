## 2. Деплой и маршрутизация
- Хостинг: VPS, домен https://foodfox.yuri.guru (noindex). На одном домене живут два Next-приложения.
- Workflow: `.github/workflows/deploy-web-vps.yml` → SSH на VPS → `cd /var/www/foodfox && git reset --hard origin/<ветка>` → `bash deploy/vps/update.sh`.
  - Автозапуск по push только при изменениях в `apps/web/**`, `packages/database/**`, `deploy/vps/**`, `VERSION` или самом workflow. **Изменения только в `apps/site` сами не деплоятся** — запускать вручную:
    `gh workflow run deploy-web-vps.yml --ref cursor/partner-cabinet-auth-5e5b` (≈4 мин; при разовом сбое — `gh run rerun <id>`).
- `deploy/vps/update.sh`: сначала собирает apps/web (pm2, :3030), потом apps/site: `SITE_PORT=3041`, `SITE_ASSET_PREFIX=/_site`, `npm ci && next build`, pm2-процесс **`foodfox-site`** (`next start -H 127.0.0.1 -p 3041`), проверка `/` и одного ассета `/_site/_next/static/...`.
- `deploy/vps/nginx-apply.sh` (управляемый блок «BEGIN foodfox routing»):
  - `/api/` → apps/web :3030, но `= /api/lead` → apps/site :3041;
  - `^~ /_next/` → apps/web; `^~ /_site/` → apps/site со срезанием префикса (поэтому в `next.config.mjs` `assetPrefix: process.env.SITE_ASSET_PREFIX`);
  - `/(partner|login|account|chat|plan|recipes|results|upload)` и `robots.txt|favicon.ico|icon.png|fox-logo.png|onboarding-hero.jpg` → apps/web;
  - всё остальное (`/`) → apps/site, включая его 404.
- После каждого деплоя: `curl` 200 на `/`, `/partner/apply`, `/api/health`; `node tools/tops.mjs https://foodfox.yuri.guru <out>` (контраст шапки на 16 страницах × 1440/390, ожидается «OK: header readable on all pages»).
- Коммиты от `x3-team <x3-team@users.noreply.github.com>`; деструктивные git-операции (force-push, reset опубликованного) — только с подтверждением заказчика.
