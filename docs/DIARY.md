# Дневник симптомов (экран 14)

Клиент раз в день отмечает самочувствие (3 варианта), симптомы (5 из макета), по желанию заметку и что ел. Записи видны в приложении списком и календарём, привязаны к неделе и фазе плана и к зонам продуктов из отчёта FOX. Ассистент в чате раз в день мягко напоминает заполнить дневник.

Макет: Figma `BgW10eEDt4u0udy0qlKuy0`, секция «Клиент · Дневник и состояния», фрейм `1122:603`.

## Что есть в макете и что дорисовано

По макету: заголовок и подпись, карточка «Как сегодня самочувствие?» (Плохо / Так себе / Хорошо, выбор заливается за 160 мс), «Симптомы» (Вздутие, Кожа, Энергия, Сон, ЖКТ), «Сохранить запись» (после сохранения галочка draw-in 300 мс), «Последние записи» строками с точкой, датой, самочувствием и симптомами.

Дорисовано в стиле приложения (в макете нет):

1. Плашка «Неделя N · Фаза» под заголовком: связь с планом.
2. Свёрнутые строки «+ Что ели · необязательно» и «+ Заметка · необязательно». «Что ели» предлагает продукты из плана на сегодня и даёт добавить свои.
3. Подсказка на красном фоне, если в записи есть продукт из красной зоны клиента («…в красной зоне по вашему отчёту. На этапе элиминации такие продукты исключаем.»).
4. Переключатель «Список / Календарь» и календарь месяца: день закрашен цветом самочувствия, сегодня обведено, будущие дни бледные.
5. Шторка дня: дата, неделя и фаза, самочувствие, симптомы, продукты с точкой зоны, заметка, «Изменить», «Удалить запись» (с подтверждением).
6. Форма для прошлого дня в шторке (тап по пустому дню календаря, до 30 дней назад).
7. Карточка «Самочувствие по фазам плана»: число записей и полоска хорошо / так себе / плохо по каждой фазе.
8. Состояние «Записей пока нет», «Показать все записи» после 7 строк, «записано» в карточке, если сегодня уже отмечено, кнопка «Обновить запись».
9. В чате под напоминанием ассистента кнопка «Открыть дневник».

Экран открывается из профиля («Дневник симптомов») и из чата. Он открывается поверх таббара, как загрузка отчёта; в макете таббар виден.

Скриншоты: папка проекта `symptom-diary/`.

## API (apps/web)

`GET /api/diary?days=62` возвращает `context` (сегодня по UTC, есть ли план, неделя и фаза сегодня, дата старта плана, до 12 продуктов из плана на сегодня, окно правки 30 дней) и `entries` (новые сверху).

`PUT /api/diary` с телом `{date, wellbeing, symptoms, note?, foods?}` создаёт или заменяет запись за день. `wellbeing`: `bad | so_so | good`. `symptoms`: подмножество `bloating, skin, energy, sleep, gut`. Заметка до 500 символов, до 20 продуктов по 60 символов. Дата: локальный день клиента, не позже завтрашнего по UTC (Москва впереди UTC) и не раньше 30 дней назад.

`DELETE /api/diary?date=YYYY-MM-DD` удаляет запись.

Продукты получают зону из отчёта самого клиента только при точном совпадении названия (без учёта регистра и ё). Догадки вроде «сыр» → «Сыр козий» не делаются: неверная зона рядом с симптомом хуже, чем никакой.

## Защита медданных

- Самочувствие, симптомы, заметка и продукты (с зонами) хранятся только внутри `diary_entries.payload`, зашифрованными AES-256-GCM на стороне API (`apps/web/src/lib/health-crypto.ts`). В базе, дампах и бэкапах лежит шифротекст. Открытыми остаются клиент, дата и номер недели.
- Шифротекст привязан к клиенту и дню (associated data): скопированный в чужую строку не откроется.
- Ключ `FOX_HEALTH_DATA_KEY` (32 байта, `openssl rand -base64 32`). В production без ключа дневник отвечает 503, остальное API работает. Вне production используется фиксированный dev-ключ, которым нельзя открыть боевые данные.
- RLS на `diary_entries` (политика по `app.client_id`, с `WITH CHECK`), все запросы дневника идут в клиентском контексте (`db-context.ts`). При удалении клиента записи удаляются каскадом.
- Ответы с `Cache-Control: no-store`, в приложении дневник не кладётся в кэш ответов.
- Содержимое записей не пишется в логи и в GlitchTip: в отчёт об ошибке уходит только маршрут и тип ошибки.
- AppMetrica получает одно событие `diary_entry_saved` с параметром `from` (`profile` или `chat`). Ни самочувствия, ни симптомов, ни продуктов, ни даты. Это проверяет тест `test/diary_test.dart`.

## Напоминание в чате

При открытии чата сервер добавляет сообщение типа `diary_reminder`, если у клиента активный план, за сегодня ещё нет записи и такого напоминания сегодня ещё не было. Ошибка в этой проверке чат не ломает. В историю для LLM напоминание не попадает (туда идут только `chat`).

## Миграция

`packages/database/migrations/010_symptom_diary.sql`: таблица, индекс, RLS, новый тип сообщения `diary_reminder` в CHECK на `chat_messages.message_type`. Номер 010 выбран, чтобы не пересекаться с миграциями админки сайта (004, 005, …); от них не зависит. Применяется сама при первом запросе (`ensureSchema`), повторный запуск безопасен.

## Деплой сервера

Сервер на VPS деплоится из `cursor/mvp-web-prototype-5e5b`, поэтому до переноса туда дневник на боевом API не работает: приложение покажет ошибку загрузки на экране дневника, остальное не затронуто.

1. Сгенерировать ключ `openssl rand -base64 32`, положить `FOX_HEALTH_DATA_KEY` в `/var/www/foodfox/apps/web/.env` и сохранить копию отдельно от сервера. Потеря ключа означает потерю записей. Смена ключа пока не поддержана (формат `v1:` оставляет для неё место).
2. Перенести в `cursor/mvp-web-prototype-5e5b` серверную часть: `apps/web/src/lib/{diary,diary-store,diary-memory,health-crypto}.ts`, `apps/web/src/app/api/diary/route.ts`, правки `apps/web/src/lib/db.ts` (список миграций и напоминание), миграцию 010, `deploy/vps/*`. Маршрут использует `lib/monitoring.ts` из PR #12, которого в той ветке тоже ещё нет, так что переносить вместе с ним.
3. Деплой через `deploy-web-vps.yml` заменяет живой сайт и кабинет: согласовать с проектом «FOX - сайт».

Проверка после деплоя: `update.sh` печатает `FOX_HEALTH_DATA_KEY: set`; `GET /api/diary` с токеном клиента отвечает 200.

## Тесты

- `apps/web`: `npm run diary:test` (правила ввода, зоны, шифрование, сохранение/чтение/удаление в памяти). С `DIARY_TEST_DATABASE_URL=postgres://…` тот же прогон идёт на Postgres и проверяет, что в таблице лежит шифротекст.
- `apps/mobile`: `flutter test test/diary_test.dart` (модели, экран по макету, сохранение и тело запроса, подсказка о красной зоне, событие аналитики только с `from`, календарь, удаление, кнопка в чате).

## Не сделано

- Смена ключа шифрования.
